# Подготовительные примеры

Небольшое ДЗ перед подключением Hollow Knight: один нейрон, змейка и Gymnasium. Оно помогло разобраться с входами и весами, обновлением параметров, наградой и циклом взаимодействия со средой.

## Что в коде

- `neuron.py` — один NumPy-нейрон на четырёх примерах. Считает `X @ w`, применяет сигмоиду и меняет веса через `X.T @ delta`.
- `snake.py` — три линейных нейрона, по одному на действие. Вход — восемь признаков, веса — матрица 3×8. Обучающая цель строится из награды и оценки будущего.
- `cartpole/01_probe.py`–`07_spaces.py` и `model.py` — запрос к среде, случайное управление, сбор данных, обучение сети, оценка и просмотр игры.

Нейрон вычисляет взвешенную сумму входов и применяет функцию активации. Функция потерь измеряет ошибку, а эпоха — один проход по обучающей выборке. В NumPy-примере используется сигмоида, в сети CartPole — ReLU. Змейка учится по награде; сеть CartPole повторяет готовое правило управления.

## Запуск

Из этой папки, с Python 3.12:

```bash
LAB_PYTHON="$(python3.12 -c 'from pathlib import Path; import sys; print(Path(sys.executable).resolve())')"
"$LAB_PYTHON" -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python neuron.py
.venv/bin/python snake.py
```

На Windows окружение создаётся командой `py -3.12 -m venv .venv`; далее вместо `.venv/bin/python` используется `.\.venv\Scripts\python.exe`. `snake.py` обучается 300 партий, ждёт Enter и показывает игру в консоли.

CartPole запускается последовательно:

```bash
.venv/bin/python cartpole/01_probe.py
.venv/bin/python cartpole/02_random.py
.venv/bin/python cartpole/07_spaces.py
.venv/bin/python cartpole/03_collect.py
.venv/bin/python cartpole/04_train.py
.venv/bin/python cartpole/05_evaluate.py
.venv/bin/python cartpole/06_watch.py
```

У случайного агента есть `--headless`. Данные и веса создаются в `output/`, которая исключена из Git. Повторное обучение перезаписывает результаты своего предыдущего запуска.

Gymnasium возвращает из `reset()` пару `(observation, info)`, а из `step()` — `(observation, reward, terminated, truncated, info)`. После любого завершения нужен новый `reset()`. Падение относится к `terminated`, внешний лимит — к `truncated`.

## Что получилось

Опыты выполнены на macOS arm64, Python 3.12.11 и CPU; версии пакетов указаны в `requirements.txt`. Точные числа и настройки сохранены в [results.json](results.json).

| Опыт | Результат |
|---|---|
| Один NumPy-нейрон | После 10 000 эпох верно разделил четыре обучающих примера по порогу 0,5 |
| Змейка, исходная награда | В среднем 17,40 яблока за оценочную партию |
| Змейка, награда за каждый ход жизни | 0,71 яблока: агент преимущественно доживал до голода |
| CartPole, случайное управление | В среднем 20,3 шага на 20 эпизодах |
| CartPole, необученная сеть | 9,3 шага |
| CartPole, обученная сеть 4→16→2 | 500 шагов во всех 20 эпизодах — лимит среды |
| CartPole, вариант 4→8→2 | Тоже достиг лимита; параметров 58 вместо 114 |

Для змейки проведено по пять обучений на вариант награды и по 20 новых оценочных партий каждого агента. Этот локальный протокол разделял случайность игры и случайных действий; исходный `snake.py` использует общий генератор и одной командой не воспроизводит таблицу. Для каждой архитектуры CartPole выполнено одно обучение, поэтому сравнение не устанавливает превосходство одной сети над другой.

Практический вывод для Hollow Knight: нужно отдельно проверять наблюдения и завершение эпизода, осознанно задавать награду и оценивать управление целыми попытками. Высокой точности на обучающих данных для этого недостаточно.
